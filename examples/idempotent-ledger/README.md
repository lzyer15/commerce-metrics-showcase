# 같은 자료를 다시 수집하면 숫자가 두 배가 될까

실제 `Store`의 초기화·저장 메서드를 변경 없이 추렸다. `core.py`도 원본과 같다. 외부 API와 운영 설정은 가져오지 않았다.

```sh
cd examples/idempotent-ledger
python3 demo.py
python3 -m unittest -v
```

Python 3.9 이상. 추가 패키지나 인증정보가 필요 없다. 생성된 `report.html`을 브라우저에서 열면 일별 결과·재수집 검증·입력 후보를 볼 수 있다. `result.json`에는 화면의 근거가 되는 실행 결과를 남긴다.

1. 가상 주문 두 개를 실제 SQLite 저장 로직으로 기록한다.
2. 같은 자료를 다시 넣고 레코드 수와 합계가 유지되는지 확인한다.
3. 환불 원천 금액을 수정해 다시 넣고 기존 레코드가 갱신되는지 확인한다.
4. 수집하지 않은 날짜는 빈 값과 보류로 표시한다.

| 확인 | 결과 |
|---|---|
| 같은 자료 두 번 수집 | 레코드 2개, 결제 합계 200,000원 유지 |
| 환불 원천 수정 | 30,000원에서 40,000원으로 갱신 |
| 수집 완료·실적 없는 날짜 | 실제 0 유지 |
| 미수집 날짜 | 빈 값 유지, 입력 후보에서 제외 |

저장은 프로덕션 메서드이며 화면·합계 표시·입력 후보 생성은 이 공개 예제의 보조 코드다. 화면은 실행 결과를 보기 위한 것이며 실제 운영 대시보드가 아니다. Google Sheets 쓰기와 원천 대조 자격은 이 예제에 포함하지 않는다.

원본 메서드와 파일의 해시는 [source-provenance.json](source-provenance.json)에 기록했다. 실제 고객·실적·계정 데이터는 사용하지 않았다.
