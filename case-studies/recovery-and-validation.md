# 다시 가져와도 숫자가 불어나지 않게

수집은 한 번에 끝나지 않았다. 조회가 늦게 반영되기도 하고, 환불처럼 나중에 생기는 사건도 있었다. 재시도와 재대조를 정상적인 운영 과정으로 넣었다.

## 원장을 남기고 다시 집계한다

SQLite에 플랫폼·계정·원천 식별자를 기준으로 기록한다. 같은 자료를 두 번 수집해도 중복 합산하지 않는다. 뒤늦게 바뀐 사건은 다시 반영하고, 필요한 기간을 재집계한다.

원천 식별자는 내부 대조에 필요한 정보만 남긴다. 고객 이름·이메일·배송 주소를 저장하지 않는 동작도 합성 응답으로 검증한다.

## 전날 수집과 재대조를 나눈다

일간 수집은 최근 값을 채우고, 주간·월간 재대조는 늦게 바뀐 값을 확인한다. 실행 상태와 대기 구간을 기록해 실패한 부분을 다시 처리한다. 플랫폼별 실패가 다른 플랫폼의 확인된 값까지 지우지 않게 한다.

## 실행 성공과 데이터 확인을 구분한다

프로세스 완료, 원천 조회 완료, 입력 검증, 입력 후 재조회는 서로 다른 확인이다. 수동으로 과거 기간을 채웠다는 사실도 다음 예약 실행의 성공을 대신하지 않는다.

운영 점검·알림·백업 도구를 붙였다. 기존 운영 기록에는 서버 실행과 시트 재조회 근거가 있지만, 외부에서 서버 자체의 중단을 감지하는 감시는 남은 작업이다.
