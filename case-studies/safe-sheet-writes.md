# 보고서를 바꾸지 않고 입력을 바꿨다

기존 보고서에는 이미 수식과 피벗, 수기로 관리하던 항목이 있었다. 새 대시보드로 옮기기보다 기존 사용 흐름을 유지하는 편이 맞았다.

## 원본 셀만 쓴다

보고서 탭을 덮어쓰지 않는다. 정해진 원본 열과 날짜의 셀만 입력 계획에 넣는다. 대상 시트·탭·시간대·헤더·날짜 배열을 확인하고, 허용하지 않은 열이나 수식 셀은 보호한다.

## 계획과 입력을 나눈다

수집 결과에서 입력 계획을 만든 뒤 대상과 범위를 검증한다. 시험 복사본에서 확인한 흐름을 승인된 운영 경로에 적용했다. 일반 시험 입력 경로는 원본 대상에 쓰지 못하도록 막는다.

운영 경로에서도 대조가 끝난 값만 입력하고, 미확인 값이나 원천 누락은 기존 값을 덮어쓰지 않도록 보류한다. 자동 탭에는 소유 표시를 확인하고 정해진 범위만 쓴다.

## 쓴 뒤 다시 읽는다

API 응답이 성공했다고 입력까지 끝난 것으로 보지 않는다. 대상 셀을 다시 읽고 계획과 비교한다. 날짜 이동, 헤더 변경, 중복 날짜 같은 구조 문제는 쓰기 전에 중단한다.

기존 보고서를 유지하면서 입력 과정에 확인 단계를 붙인 작업이다. 사용자는 보던 보고서를 계속 보고, 수집기는 자신이 맡은 셀만 관리한다.
